# Role-to-skill roadmap

This roadmap is an **interpretation of public job responsibilities**, not a prediction of interview rounds.

| Capability | What a strong candidate demonstrates | Evidence to prepare |
| --- | --- | --- |
| Discover | Asks about user, data, workflow, constraints, decision owners | One-page discovery brief |
| Scope | Defines narrow MVP, success/failure gates, owners | Two-phase delivery plan |
| Build | Writes clear, tested Python/JS and handles edge cases | Working service + tests |
| Evaluate | Measures quality on representative cases, segments failures | Versioned eval set + error taxonomy |
| Secure | Separates untrusted model output from authorized actions | Threat model + approval boundary |
| Launch | Implements telemetry, rollback, runbooks, adoption monitoring | Production checklist |
| Feedback | Turns recurring failures into reusable fixes | Product feedback memo |

## Practice emphasis

Allocate **more time to applied delivery and empirical validation** than memorizing model trivia. The public role stresses full-stack work, deployment ownership, and evaluation-driven field feedback. Python and JavaScript are mentioned as example stacks; choose one and be ready to work across interfaces.

## Evidence portfolio

Prepare three short stories: (1) an ambiguous customer problem you scoped, (2) a production incident or complex bug you resolved, (3) a rollout whose adoption/impact you measured. For each, name baseline, trade-offs, your code contribution, failures, and outcome. Never invent production outcomes.
